## 一、作业概述

本次作业在同一个 CubeMX 工程中完成三道题，开发板为 STM32F103C8T6 最小系统板。

- 题目一 GPIO：把 PC13 配置为推挽输出，在初始化里输出低电平，点亮板载 LED。
- 题目二 定时器：用 TIM2 的更新中断产生 1 ms 周期，在中断回调里让全局变量 tick 自增 1，并调用 HAL_IWDG_Refresh 喂狗。
- 题目三 看门狗：去掉回调里的喂狗，观察 IWDG 超时复位，tick 从 0 涨到约 2000 再回到 0，循环往复。

三题都不关闭 IWDG。题目二、题目三分两次下载、分两次截图。

## 二、工程与工具链

- CubeMX 6.18.1 生成工程：Toolchain/IDE 选 CMake，勾选 Generate Under Root。
- 用发放的 CMakeLists.txt 替换了 CubeMX 生成的那一份，其中 user_folders 保持 "Tasks"。
- 在工程根目录建立 Tasks/inc 与 Tasks/src，业务代码只写在这两个目录。
- main.c 里只在 USER CODE 区域 #include "task.h" 并调用 Task_Init()，while(1) 保持为空。
- 编译：CMake + Ninja + arm-none-eabi-gcc，构建类型选 Debug；产物在 build/ 目录下，用 Ozone 打开 build/ec_hw1.elf。

## 三、题目一：GPIO

- 在 CubeMX 中把 PC13 配置为 GPIO_Output，模式为推挽输出（Output Push Pull），初始电平为低，用户标签 LED。
- 在 Tasks 的初始化函数 Task_Init() 中再显式拉低一次：HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET)。
- 板载 LED 一端接电源、一端接 PC13，所以引脚输出低电平时 LED 点亮。
- 不要求在 while(1) 里翻转，因此灯保持常亮。
- 现象：板子上电后 LED 常亮。照片见附录。

## 四、题目二：定时器（TIM2，1 ms）

时钟来源：

- 板载 8 MHz 晶振（HSE）作为 PLL 输入，PLL 倍频 9 倍，得到系统时钟 SYSCLK = 8 MHz × 9 = 72 MHz。
- AHB 不分频，HCLK = 72 MHz。
- APB1 分频系数为 2，所以 APB1 时钟 = 36 MHz。
- TIM2 挂在 APB1 上，且 APB1 分频不为 1，此时定时器时钟等于 APB1 时钟的 2 倍，即 36 MHz × 2 = 72 MHz（与 CubeMX 时钟树显示一致）。

周期计算：

- 中断周期 = (PSC + 1) × (ARR + 1) ÷ 定时器时钟。
- 令 PSC = 71，ARR = 999：(71 + 1) × (999 + 1) ÷ 72000000 = 72000 ÷ 72000000 = 0.001 s = 1 ms。

实现：

- Task_Init() 里调用 HAL_TIM_Base_Start_IT(&htim2) 启动更新中断。
- 全工程只定义一份回调 HAL_TIM_PeriodElapsedCallback()，放在 Tasks/src/task.c；CubeMX 未生成同名函数。
- 回调里：tick++；再调用 HAL_IWDG_Refresh(&hiwdg) 喂狗。
- tick 定义为全局 volatile uint32_t，名字必须为 tick，这样 Debug 下 Ozone 才能在变量窗口看到并画曲线。

现象：tick 大约每秒增加 1000。Ozone 截图见附录。

## 五、题目三：看门狗（IWDG）

- IWDG 保持启用，分频与重装载值不改。
- 分频（Prescaler）= 64，重装载值（Reload）= 1249。
- LSI 取手册值：F103 约 40 kHz。
- 超时时间 = (Reload + 1) × 分频 ÷ LSI = (1249 + 1) × 64 ÷ 40000 = 80000 ÷ 40000 = 2.0 s。

修改：把 Tasks/src/task.c 里的宏 FEED_WATCHDOG 由 1 改为 0，去掉回调里的 HAL_IWDG_Refresh，重新编译下载。

现象：tick 仍然每 1 ms 加 1，但因为不喂狗，约 2 s 后 IWDG 超时，芯片复位。复位后启动代码把全局变量清零，于是 tick 从 0 涨到约 2000（2 s × 1000/s）再回到 0，并不断重复。Ozone 截图见附录。

注意：用 Ozone 观察时让程序保持运行，不要停在断点上——CPU 停住时看门狗仍在计数，会复位导致调试器掉线。

## 六、小结

- 三个功能共用一个工程，靠一个宏在“定时器题”和“看门狗题”之间切换。
- 关键点：时钟树 → 定时器时钟 → PSC/ARR；LSI → 分频/Reload → IWDG 超时。
