# 电控第一次作业 说明文档

## 一、这次作业做了什么

这次作业一共三道题，都放在同一个 CubeMX 工程里，用的板子是 STM32F103C8T6 最小系统板。

- 第一题 GPIO：让板载灯亮起来
- 第二题 定时器：用 TIM2 每 1ms 中断一次，让 tick 加 1，并且喂狗
- 第三题 看门狗：把喂狗去掉，看芯片会不会自己复位

三题都一直开着 IWDG，没有关掉。第二题和第三题我是分两次下载、分别截的图。

## 二、工程是怎么搭的

- 用 CubeMX 生成工程，Toolchain/IDE 选 CMake，勾了 Generate Under Root。
- 生成完之后把它自带的 CMakeLists.txt 删掉，换成学长发的模板，里面的 user_folders 我没动，保持 "Tasks"。
- 在工程根目录建了 Tasks/inc 和 Tasks/src，我自己的代码都写在里面。
- main.c 里我只在 USER CODE 那几段里写了东西：包含一下 task.h，然后调用 Task_Init()，while(1) 里没写东西。
- 编译用的是 CMake + Ninja + arm-none-eabi-gcc，构建类型选 Debug。生成的 .elf 在 build 目录里，用 Ozone 打开它来调试。

## 三、第一题：GPIO

- 在 CubeMX 里把 PC13 配成 GPIO_Output，模式是推挽输出（Output Push Pull），初始电平低，标签写的是 LED。
- 在 Tasks 的 Task_Init() 里我又拉低了一次：HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
- 板子上灯的正极接电源、负极接 PC13，所以 PC13 输出低电平的时候灯就亮了。
- 题目说不要在 while(1) 里翻转，所以我初始化设完就没再动，灯一直亮着。
- 现象：上电后板载灯常亮。照片在附录 A。

## 四、第二题：定时器

时钟这块我是照着 CubeMX 的时钟树算的：

- 板子上是 8MHz 的晶振（HSE），PLL 倍频 9 倍，所以系统时钟 SYSCLK = 8 × 9 = 72MHz。
- AHB 不分频，HCLK = 72MHz。
- APB1 分频是 2，所以 APB1 = 36MHz。
- TIM2 挂在 APB1 上，而且 APB1 分频不是 1，所以定时器时钟是 APB1 的 2 倍，也就是 36 × 2 = 72MHz（跟 CubeMX 时钟树上显示的一样，我就按这个算）。

然后算 PSC 和 ARR，公式是：中断周期 = (PSC+1) × (ARR+1) ÷ 定时器时钟。
我想让它 1ms 中断一次，也就是 0.001s，取 PSC = 71，ARR = 999：
(71+1) × (999+1) ÷ 72000000 = 72000 ÷ 72000000 = 0.001s，正好 1ms。

代码这边：

- Task_Init() 里调用 HAL_TIM_Base_Start_IT(&htim2) 开更新中断。
- 回调函数 HAL_TIM_PeriodElapsedCallback() 整个工程只写了一份，放在 Tasks/src/task.c 里。CubeMX 没有生成同名的函数，所以没有重复定义。因为我是用 C 写的，不用加 extern "C"。
- 回调里就是 tick 加 1，然后调用 HAL_IWDG_Refresh(&hiwdg) 喂狗。
- tick 定义成全局的 volatile uint32_t，名字就叫 tick，这样在 Ozone 里能看到它，也能画曲线。

现象：tick 大概每秒涨 1000。截图在附录 B。

## 五、第三题：看门狗

- IWDG 还是开着，分频和重装载值都没改。
- 分频是 64，Reload 是 1249。
- LSI 手册上写 F103 大约是 40kHz，我按 40kHz 算。
- 超时时间 = (Reload+1) × 分频 ÷ LSI = (1249+1) × 64 ÷ 40000 = 80000 ÷ 40000 = 2s。差不多 2 秒，比 1ms 大很多，没问题。

改的地方：把 Tasks/src/task.c 里的宏 FEED_WATCHDOG 从 1 改成 0，也就是把回调里的 HAL_IWDG_Refresh 去掉了，然后重新编译下载。

现象：tick 还是每 1ms 加 1，不过因为不喂狗了，大概 2 秒后 IWDG 超时，芯片复位。复位之后全局变量被启动代码清掉了，所以 tick 会从 0 涨到大约 2000（2 秒 × 每秒 1000 次），然后回到 0，就这样一直重复。截图在附录 C。

还有一点：在 Ozone 里看的时候程序要保持运行，不能停在断点上。因为 CPU 一停，看门狗还在数，过一会就复位了，调试器会掉线。

## 六、小结

三题放在一个工程里，用 FEED_WATCHDOG 这个宏在“定时器题”和“看门狗题”之间切换。
关键就是：先看时钟树确定定时器时钟，再算 PSC/ARR；看门狗那边是用 LSI 和 分频/Reload 算超时。
